# Technical audit report – qqrtools 0.3.0

Scope: full review of the R package previously published as `qqr`
(GitHub `Baffour536/qqr`, commit `f6d4aee`) and of the local development
material, consolidation into the release candidate `qqrtools` 0.3.0, and
correction of the defects found. Audit date: 13 November 2026. Platform used:
Windows 11, R 4.6.2.

**How the authoritative version was established.** A function inventory was
extracted from every R file in every location and compared with
`Packages/qqr/R/`. No function defined anywhere else was missing from
`Packages/qqr/R/` (the only extra symbol, `out`, is a local variable in the
example scripts). `git status` in `Packages/qqr` showed that `qqr-core.R`,
`qqr-qr.R` and `qqr-utils.R` were identical to GitHub and that the new work
was in `qqr-methods.R` (+2,355 lines), `qqr-export.R`, the documentation, the
tests and the vignette. The local version therefore extends the GitHub
version without removing anything, and it was adopted as the base.

**Not carried into the package (left untouched on disk):** all data,
presentations, PDFs, images, result workbooks, library-repair scripts, the
older snapshots, `.Rhistory`/`.RData` files and the built tarball. One
development script (`dev/01-setup.R`) contains an absolute local path to a

## 2. Architecture assessment

Structure follows standard R package layout (`DESCRIPTION`, `NAMESPACE`
generated by roxygen2, `R/`, `man/`, `tests/testthat/`, `vignettes/`,
`inst/CITATION`). Findings:

* `R/qqr-methods.R` (3,000+ lines) mixes print methods, five plotting
  systems and the dependence heatmap. It was left in one file to keep the
  diff reviewable; splitting it is listed as future work.
* A second definition of `.qqr_match_coef()` in `qqr-methods.R` silently
  replaced the one in `qqr-core.R` (files are collated alphabetically) and
  dropped the backward-compatibility branch. Removed.
* `dplyr` and `tidyr` were hard imports used only to reshape one table.
  Replaced by base R; Imports are now `graphics`, `grDevices`, `quantreg`,
  `stats`.
* S3 methods are both registered and exported by name (e.g.
  `compare.qqr`). This is kept for backward compatibility (users call them
  directly); it is permitted by `R CMD check`.
* The generic `compare()` has the same name as `testthat::compare()`; when
  both packages are attached, the later one masks the other. Kept for
  compatibility and documented.
* All examples were wrapped in `\dontrun{}`; none were ever executed by
  `R CMD check`. All are now runnable (file output goes to `tempdir()`,
  interactive *rgl* code runs only in interactive sessions, *plotly* and
  export examples are guarded by `requireNamespace()`).
* `.Rbuildignore`/`.gitignore` updated (CI files, audit reports, validation
  scripts, check folders, tarballs, `Rplots.pdf`). `qqr.Rproj` renamed to
  `qqrtools.Rproj`. `.gitattributes` normalises line endings to LF.

## 3. Defects found and corrections made

Severity: **Critical** = produces wrong estimates or wrong scientific
conclusions without warning; **Major** = wrong output in a documented use
case; **Minor** = cosmetic, misleading documentation or robustness.

| # | Severity | Defect | Correction |
|---|---|---|---|
| 1 | Critical | **Grid not at quantiles.** The grid was `seq(min(x), max(x), length.out = m)`, but the vignette, help pages and Sim and Zhou (2015) define the surface at quantiles of the regressor, and `plot.qqr()`, `Int.plot()`, `surface3d()` labelled the rows `seq(0.05, 0.95)` as if they were quantiles. With skewed or heavy-tailed regressors most grid points fell in sparse tails and the axis labels were false. | New default `grid = "quantile"` (grid at `quantile(x, thetas)`); `thetas` stored and used by all plots; `grid = "range"` reproduces 0.2.0 with correct `thetas = F_n(grid)`. |
| 2 | Critical | **`compare.qqr()` compared unrelated numbers.** It computed `rowMeans` (average over tau for each grid point) and paired grid point *j* with tau *j*. The documented Sim–Zhou check averages over theta for each tau. | Now `colMeans` of the surface for each tau vs `rq()` on the same design; `difference` column; message when `grid = "range"`. |
| 3 | Critical | **Factor controls and transformed regressors silently produced all-`NA` surfaces.** Coefficient names from `rq()` (e.g. `fb`) did not match variable names (`f`), and a formula such as `y ~ log(xp)` was re-parsed against a data frame that had a column called `"log(xp)"`, so every local fit failed inside `tryCatch` and returned `NA`. | Local fits use the model matrix with safe column names; coefficient names are model-matrix columns. Verified by tests (factor dummies estimated; `log(x)` fit identical to fitting on `x`). |
| 4 | Major | **`cv_fast` ignored the outcome.** The selector predicted `x_i` by a kernel-weighted median of the other `x` values, a criterion that always improves as *h* shrinks, so it nearly always returned the smallest candidate. | LOO check-loss CV of a kernel-weighted median of `y` given `x`, verified against a brute-force implementation. |
| 5 | Major | **plotly colour scales reversed.** `reversescale = TRUE` was applied to diverging palettes whose low end is already blue, so negative coefficients were drawn red, contrary to the documentation. Unknown names such as `"Plasma"` were silently replaced by plotly's default. | Explicit colour scales (low = blue for RdBu), `hcl.pals()` palettes supported, no `reversescale`. |
| 6 | Major | **Somers' D(Y\|X)** used pairs tied on *X* in the denominator, i.e. computed D(X\|Y). | Denominator uses pairs tied on *Y* but not *X* (Somers, 1962); verified against a brute-force count. |
| 7 | Major | **Co-exceedance** in `qqr_cor_heatmap()` used lower bin boundaries as thresholds while the independence benchmark used the tau mid-points; the first bin break was the `tau_1/2` quantile instead of the minimum. | Thresholds at the tau-quantiles over the full sample; benchmark returned as `$independence`; line drawn where observed = benchmark; first break = minimum. |
| 8 | Major | `qqr_surface(tau_subset = 0.1)` used exact floating-point matching; `0.1` from `seq(0.05, 0.95, by = 0.05)` is not exactly 0.1, so the column was silently dropped. | Matching with tolerance 1e-8; unmatched values are an error. |
| 9 | Major | No validation of `taus`, `m`, `thetas`, empty data, constant or non-numeric regressor, infinite values, interactions with the regressor; zero-variance `x` gave `h = 0` and `NaN` weights. | Explicit checks with informative errors (tests in `test-validation.R`). |
| 10 | Major | Failed local fits (too few effective observations, collinearity, solver errors) were silently `NA`. | Counted in `n_failed`, one summary warning; rank and Kish-ESS checks before fitting. |
| 11 | Minor | `effective_n` was the sum of kernel densities, not an effective sample size. | Kish effective sample size (Σw)²/Σw². |
| 12 | Minor | `print`/`summary` labels only covered 4 of 8 bandwidth methods (and a non-existent `"cv"`). | Labels for all methods. |
| 13 | Minor | `word.qqr(which = "coef_stars")` printed a dagger for missing p-values (README/NEWS promise `[NA]`) and coefficients without fixed decimals. | `[NA]`, fixed decimals, se type in the note. |
| 14 | Minor | `panel_surface()` help described flat "ribbons of row means"; the code draws full surfaces. | Documentation corrected; x-axis uses `thetas`. |
| 15 | Minor | Citations: wrong DOI for Sim and Zhou (2015) (`…02.030`, HTTP 404) and for Yu and Jones (1998) in the README; Li and Racine (2004) attributed to *Econometrica* 72(6) / *Biometrika* 91(1); Li and Racine (2010) pages "1–31"; a reference "Li, Racine and Wooldridge (2002), *Econometrica* 70(5)" that could not be verified; a README/vignette reference "Wu (2023) … quantile-on-quantile regression approach" whose actual title (Crossref) is "…Evidence from Quantile Regression Based on Wavelet Analysis"; "Balcilar et al. (2017)" cited without a reference entry. | DOIs verified against doi.org/Crossref and corrected; Li and Racine (2004) → *Statistica Sinica* 14(2), 485–512; Li and Racine (2010) → 26(6), 1607–1637; unverifiable references removed or replaced by Li, Huang, Li and Fu (2002), *JBES* 20(3), 412–422 (verified). |
| 16 | Minor | `qqr_cor_heatmap()` printed `?` instead of arrows (encoding damage) and its argument check `any(is.null(c(...)))` could never trigger. | Fixed. |
| 17 | Minor | `qqr_heatmap(coef = "intercept")` failed; `clim` not validated in several plot functions. | Common coefficient resolver and `clim` validation. |
| 18 | Minor | `tools::toTitleCase()` used without declaring `tools`. | Removed. |

## 5. Performance

See `TESTING_REPORT.md` §5 for timings. The cost is dominated by
`m × K` calls to `quantreg::rq()`; p-value computation (`se_type = "nid"`)
roughly doubles it. `cv_fast` is O(15 n²) and becomes slow above a few
thousand observations; this is documented. No optimisation that could
change numerical results was made.

## 6. Remaining limitations

* Pointwise p-values do not account for smoothing bias, bandwidth
  selection or multiple testing (documented; quantified in
  `ECONOMETRIC_VALIDATION_REPORT.md`).
* Automatic bandwidths are density/mean-regression rules, not optimal for
  QQR slopes; at the default Silverman rule the local slope surfaces are
  noisy in samples of a few hundred observations (quantified in the
  validation report). Users must report *h* and check sensitivity.
* Only the Gaussian kernel is implemented.
* No bootstrap confidence bands or uniform inference for the surface.
* `qqr-methods.R` is large; splitting it would ease maintenance.
* `npcv` and `sc` bandwidths are delegated to *np* and were run but not
  independently verified.
* Graphics are verified to run and to use the correct axes/colour
  orientation; their visual appearance was not reviewed image by image.
